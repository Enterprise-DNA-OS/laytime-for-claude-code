# Why there is no front end

The useful work is reviewing the charter evidence, counting time and resolving the claim. The records live in Postgres or embedded PGlite. A coding agent runs the documented CLI and presents the result. The same records produce branded read-only HTML statements and reports.

A screen can provide direct mobile entry, document annotation, drag and drop, a graphical event timeline, offline vessel capture and multi-user permissions. This base has none of those. It does not ingest an inbox or read scanned handwriting. Enterprise DNA can build the specific capture, review and access flow a business needs around the same records.

Keep source documents in a controlled store. Import only the supported text PDF layout and verify it. Read-only reports are private working files; do not publish them. The database and its access rules, not an HTML report, govern who can change records.
